## ПР2. Ответы на контрольные вопросы

### 1. Почему для хранения денег используют `decimal`, а не `double`? Что может пойти не так с `double`?

`double` хранит число в двоичном формате с плавающей точкой: как мантиссу и степень двойки.
В двоичной системе большинство «круглых» десятичных дробей (0.1, 0.2, 0.7) не представимы точно,
они хранятся с погрешностью около 10⁻¹⁶. Погрешность накапливается при сложении и умножении,
и это видно на простом примере: `0.1 + 0.2` даёт `0.30000000000000004`. Для физики это неважно,
а для денег при большом числе операций появляются «лишние» копейки, и сравнение `if (sum == 100.00)`
может не сработать, хотя математически суммы равны.

`decimal` хранит число в десятичном виде (целая мантисса и степень десятки) и даёт 28–29 значащих
цифр без двоичной погрешности: `0.1m + 0.2m` — ровно `0.3`. Поэтому деньги считают в `decimal`,
хотя он занимает больше памяти (16 байт) и работает медленнее. Литерал пишется с суффиксом `m`.

### 2. Что произойдёт, если целочисленный тип (например, `byte`) переполнится?

Значение выйдет за границы диапазона, и в контексте `unchecked` (а это поведение по умолчанию)
произойдёт «заворачивание»: `byte` 255 после `++` станет 0, `sbyte` 127 станет −128,
`int.MaxValue + 1` станет `int.MinValue`. Ошибки не будет, программа молча продолжит работу
с неверным числом, и это самое опасное. Если нужен контроль, используют `checked { ... }`
или компиляцию с ключом `/checked` — тогда вместо неверного значения бросается `OverflowException`.

### 3. Чем `var` отличается от динамической типизации в Python? В какой момент компилятор определяет тип?

`var` — это статическая неявная типизация. Компилятор смотрит на выражение справа от `=` и
определяет тип один раз, во время компиляции, после чего тип зафиксирован навсегда.
`var studentAge = 20;` — это в точности `int studentAge = 20;`, и присвоить туда строку нельзя:
компилятор выдаст `CS0029: Cannot implicitly convert type 'string' to 'int'`.
`var` — только удобная запись, чтобы не писать длинный тип руками.

В Python типизация динамическая: тип привязан к значению, а не к имени, и проверяется во время
выполнения. Поэтому `x = 5`, а потом `x = "текст"` — нормально. В C# переменная не может
сменить тип на лету.

### 4. Какой тип данных всегда возвращает `Console.ReadLine()`?

Всегда `string`, независимо от того, что ввёл пользователь: число, дату или слово.
Если нужно число, строку надо преобразовать. В современном C# метод объявлен как `string?`,
то есть при завершении потока ввода он может вернуть `null`.

### 5. Чем `int.Parse` отличается от `int.TryParse` при некорректном вводе?

`int.Parse` при строке, которую нельзя разобрать как целое число (например `"abc"`), бросает
`FormatException`, и без обработки программа аварийно завершается. На `null` он бросает
`ArgumentNullException`, на слишком большом числе — `OverflowException`.

`int.TryParse` исключений не бросает: возвращает `bool` — `true`, если разбор удался, и `false`,
если нет. Само число при этом записывается в `out`-параметр.

### 6. Что означает `false`, возвращённый из `int.TryParse`, и что при этом попадёт в переменную, переданную через `out`?

`false` означает, что строку не удалось разобрать как целое число: она пустая, содержит буквы,
пробелы внутри, дробную часть или слишком велика для `int`. В `out`-переменную в этом случае
записывается значение по умолчанию для типа — `0` для `int`. Переменная всё равно считается
объявленной и заполненной, поэтому её можно сразу использовать.

### 7. Приведите пример, когда стоит использовать `TryParse`, а не `Parse` — и объясните, почему.

Основной случай — ввод с клавиатуры: пользователь может ввести «двадцать», пустую строку
или случайно нажать Enter, и `Parse` уронит программу. С `TryParse` ввод проверяется аккуратно,
и программу можно попросить повторить:

```csharp
Console.Write("Сколько вам лет? ");
if (int.TryParse(Console.ReadLine(), out int age))
{
    Console.WriteLine($"Вам {age} лет");
}
else
{
    Console.WriteLine("Нужно ввести целое число");
}
```

То же касается любых внешних данных, формат которых не гарантирован: строк из CSV, файлов
настроек, ответов API. `Parse` уместен только там, где данные точно корректны — например,
числовые константы прямо в коде.
